2. ATURAN LOGIN USERNAME + PASSWORD
==================================================

Aplikasi harus menggunakan login:

Username
Password

Bukan:

Email
Password

Tetapi karena Supabase Auth menggunakan email/password,
implementasikan sistem username abstraction.

Struktur:

profiles
- id
- user_id
- username
- full_name
- phone
- avatar_url
- role
- branch_id
- is_active
- created_at
- updated_at

Username harus UNIQUE.

Ketika user memasukkan username:

1. Validasi username
2. Cari username melalui server-side logic yang aman
3. Ambil identifier auth yang diperlukan
4. Login menggunakan Supabase Auth password authentication
5. Jangan pernah mengekspos password
6. Jangan mengirim password ke client selain proses authentication
7. Jangan membuat endpoint publik yang bisa digunakan untuk enumerasi username
8. Tambahkan rate limiting
9. Tambahkan brute-force protection
10. Tambahkan session management

Login:

/login

Field:

Username
Password

Fitur:

- Show/hide password
- Remember session
- Loading state
- Error state
- Invalid credentials
- Account inactive
- Session expired
- Logout
- Auto redirect
- Protected routes

==================================================
62. NO DATA LOSS
==================================================

Jangan melakukan destructive database migration
tanpa backup/migration strategy.

Untuk delete:

gunakan soft delete jika relevan.

Contoh:

deleted_at

Untuk transaksi keuangan:

JANGAN benar-benar menghapus data.

Gunakan:

VOID
CANCELLED
REFUNDED

==================================================
63. FINANCIAL DATA
==================================================

Jangan gunakan floating point JavaScript
untuk perhitungan uang jika menyebabkan precision issue.

Gunakan integer smallest currency unit
atau PostgreSQL NUMERIC.

Contoh:

Rp 10.000

disimpan sebagai numeric yang konsisten.

Semua perhitungan harus deterministic.

discount
tax

Sehingga laporan historis tetap benar.
